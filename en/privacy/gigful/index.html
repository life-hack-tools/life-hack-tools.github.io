Gigful Privacy Policy

The local-storage beta. Last updated: October 15, 2026.

Life Hack Tools handles information entered in Gigful as described below.

Event information on your device

Gigful stores the event name, date, venue, tickets, amounts, responsibilities, teams, lenders, deadlines, schedule, and other entered event details on your device. The current beta has no configured collaboration server and does not automatically upload this event information to a server operated by us. No account registration is required. Enter only the personal details you need, including names of people responsible for tasks.

Backups and exports

A JSON backup contains entered event information. A PDF contains the information included in the operations sheet. You choose the destination using the system file or share interface. Cloud storage and sharing apps apply their own policies. Device or operating-system backups may include app data, depending on your settings.

Retention and deletion

You can delete local events in the app. Uninstalling the app or losing a device may result in data loss; export JSON backups when needed. Deleting an event in the app does not automatically delete previously exported files or operating-system backups. Manage those copies at their respective destinations.

Support requests

The in-app support form sends your message, optional reply email, device OS and model, app version and build, and language information to form.lh.tools so we can respond. Requests sent through the website form or email are also handled using the message and contact information you provide. Do not send backups containing real names or participant information without first checking whether they are needed.

Diagnostics and distribution

The current app implementation does not collect photos or send crash logs through Sentry. The app is configured to check Expo's update service at launch. Update requests send the OS, project ID, runtime, and a random identifier for this app installation (EAS-Client-ID). This is not a hardware or advertising ID. If a previous update launch recorded a fatal error, part of that error (up to 1,024 characters) is also sent with the next update request. This information supports update delivery, recovery, and troubleshooting, separately from Sentry. Event content is not automatically attached to update requests. Operating-system or store diagnostics may be processed under the relevant providers' policies and your settings. This is separate from uploading event content.

If collaboration is enabled in a future release

Collaboration code has been prepared but is not available in the current beta. The design for an enabled release uses Firebase to process events you explicitly share or join, anonymous authentication identifiers, permissions, invitations, and update information. Before that release, we will update this policy to reflect the actual data processing, retention, deletion, and access-recovery options. This does not describe server processing currently performed by the local beta.
